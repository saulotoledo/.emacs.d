* About
This is my personal Emacs configuration, written and maintained in Org mode.

It contains my preferred packages, UI tweaks, and programming helpers. I tangle
and load the relevant Emacs Lisp from this file so the Org source is the single
source of truth for my setup. Learn more about Org mode at
[[https://orgmode.org][the Org mode website]].


* Key bindings

I am following [[https://github.com/larstvei/dot-emacs/blob/main/init.org][the dot-emacs repository]]
again on maintaining a =custom-bindings-map= that holds all my custom bindings. This is based on
[[http://stackoverflow.com/questions/683425/globally-override-key-binding-in-emacs][this StackOverflow post]].
This map can be activated by toggling a simple =minor-mode= that just activates the map, preventing other
=major-modes= from overridding these bindings.

#+begin_src emacs-lisp
(defvar custom-bindings-map (make-sparse-keymap)
  "Keymap used for user custom bindings.")

(define-minor-mode custom-bindings-mode
  "A minor mode for custom keybindings that override major modes."
  :global t
  :keymap custom-bindings-map)

(custom-bindings-mode 1)
#+end_src

** Meta settings

We start by activating [[https://www.gnu.org/software/emacs/manual/html_node/elisp/Lexical-Binding.html][Lexical binding]] to our init files. Note that we
do it with 2 files: =init.el= and =early-init.el=.

The =early-init.el= file was introduced on Emacs 27. This file, if
present, is evaluated before package and GUI initialization, which
makes it the ideal place to setup some initializations we will
introduce later.

The =init.el= is the default Emacs initialization file.

#+begin_src emacs-lisp
;;; -*- lexical-binding: t; -*-
#+end_src

#+begin_src emacs-lisp :tangle early-init.el
;;; -*- lexical-binding: t; -*-
#+end_src

We generate the =init.el= file from the source blocks in the
=init.org=. We can use =org-babel-tangle= to do this. However, to make
this process automatic after saving this file, we reuse the function
below and attach it to the =after-save-hook=. This solution is copied
from [[https://github.com/larstvei/dot-emacs/blob/main/init.org][the dot-emacs repository]].

#+begin_src emacs-lisp
(defun tangle-init ()
  "If the current buffer is init.org the code-blocks are
  tangled, and the tangled file is compiled."
  (when (equal (buffer-file-name)
               (expand-file-name (concat user-emacs-directory "init.org")))
    ;; Avoid running hooks when tangling.
    (let ((prog-mode-hook nil))
      (org-babel-tangle)
      ;; The following line is not necessary in Emacs 28+, because it
      ;; generates native compilation files (.eln) instead of .elc:
      ;; (byte-compile-file (concat user-emacs-directory "init.el"))
      ;; We use native compilation instead:
      (setq native-comp-deferred-compilation t)
      (native-compile-async (concat user-emacs-directory "init.el")))))

(add-hook 'after-save-hook 'tangle-init)
#+end_src

The Emacs Customize system utilizes the value of the variable
=custom-file= to write its customization forms. If the value of this
variable is not defined, it will write the settings to the value of
=user-init-file=, which is our =init.el= at the moment. To prevent
this from happening, we define the value of =custom-file= below:

#+begin_src emacs-lisp :tangle early-init.el
(setq custom-file (expand-file-name "custom.el" user-emacs-directory))
#+end_src

We also ensure that the cognitive-complexity package is cloned locally if it
doesn't already exist. This allows us to load it manually without relying on
package managers.

#+begin_src emacs-lisp :tangle early-init.el
;; Clone cognitive-complexity (port of codemetrics for treesit) if not already present
(let ((cognitive-complexity-dir (expand-file-name "cognitive-complexity" user-emacs-directory)))
  (unless (file-directory-p cognitive-complexity-dir)
    (message "Cloning cognitive-complexity...")
    (call-process "git" nil nil nil "clone"
                  "https://github.com/emacs-vs/cognitive-complexity"
                  cognitive-complexity-dir)))
#+end_src

Below we will load the value of =custom-file=, but we also create a
=local.el= file for local settings. This is useful for configurations
that do not need to be pushed to the git repository and that are local
to the environment in use.

#+begin_src emacs-lisp
(require 'server)
(add-hook 'after-init-hook
          (lambda ()
            (let ((local-file (concat user-emacs-directory "local.el")))
              (when (file-exists-p local-file)
                (load-file local-file))
              (when (file-exists-p custom-file)
                (load-file custom-file))
              (unless (server-running-p)
                (server-start)))))
#+end_src


** Emacs socket and server settings

When running Emacs as a daemon using `emacs --daemon`, the `(server-start)` command is
triggered implicitly, allowing the fast client, `emacsclient`, to connect. For remote
or containerized environments (like Docker), the default local file socket often
creates challenges with network exposure and file permissions. We must configure a
reliable server connection method.

*** Option 1: TCP/IP Socket (For Direct Network Exposure)

This approach is best if you want the Emacs server to listen on a network interface,
which is useful when running Emacs inside a Docker container that is exposed via
port forwarding or an SSH tunnel.

#+begin_example emacs-lisp
;; Configure the Emacs server to listen on a TCP socket
(setq server-use-tcp t)

;; Define the specific port the Emacs daemon should listen on inside the container
(setq server-port 4000)

;; Define the host interface to listen on. Setting this to "127.0.0.1" (localhost)
;; inside the container provides enhanced security, as Emacs will only accept
;; connections originating from within the container itself. This relies on the
;; external SSH tunnel to securely forward traffic to this local address.
(setq server-host "127.0.0.1")
#+end_example


*** Option 2: File Socket Directory (For Simpler SSH Forwarding)

Using a dedicated socket file location is often simpler for secure connections over
SSH, especially when using tools like `ssh -L`. This method is preferred because it
bypasses the common challenge of file permission issues associated with the default
socket location (usually in the user's home directory), which might be inaccessible
to the `sshd` process or other services. We address this directly by moving the
socket to the universally accessible `/tmp` directory, which centralizes its location
and ensures accessibility. Ultimately, given its ease of use for remote access, we
opted for this file socket approach in our configuration:

#+begin_src emacs-lisp :tangle init.el
(setq server-socket-dir "/tmp/emacs-server")
#+end_src


** Setup script

To facilitate setting up the external tools needed by our Emacs environment, we
provide a setup script that should be executed before starting Emacs.

The current version of the script requires `bash` to run: `bash setup.sh`.

**Available command-line options:**
- `--skip-java`: Skip Eclipse JDT Language Server installation
- `--skip-kotlin`: Skip Kotlin Language Server installation
- `--enable-copilot`: Enable GitHub Copilot support (requires Node.js 22.0.0+)

Without `--enable-copilot`, the minimum Node.js version is 20.19.2. With it enabled,
Node.js 22.0.0+ is required for Copilot compatibility.

We start the script by introducing some variables and command-line flags that we
will use later.

#+begin_src sh :tangle setup.sh
#!/bin/bash

SKIP_JAVA=false
SKIP_KOTLIN=false
ENABLE_COPILOT=false

parse_args() {
  for arg in "$@"; do
    case $arg in
      --skip-java)
        SKIP_JAVA=true
        shift
        ;;
      --skip-kotlin)
        SKIP_KOTLIN=true
        shift
        ;;
      --enable-copilot)
        ENABLE_COPILOT=true
        shift
        ;;
      *)
        shift
        ;;
    esac
  done
}

initialize_sdkman() {
  if [ -s "$HOME/.sdkman/bin/sdkman-init.sh" ]; then
    echo -e "\033[1;33m[ Initializing SDKMAN ]\033[0m"
    . "$HOME/.sdkman/bin/sdkman-init.sh"
    echo "SDKMAN initialized."
  else
    echo "SDKMAN not found in your environment."
  fi
}

parse_args "$@"

if [ "$SKIP_JAVA" = "false" ] || [ "$SKIP_KOTLIN" = "false" ]; then
  initialize_sdkman
fi
#+end_src

When there is no =init.el=, we must initialize it from the bootstrap file:

#+begin_src sh :tangle setup.sh
if [ ! -f "./init.el" ]; then
  echo -e "\033[1;32m\n[ Bootstraping init.el ]\033[0m"
  cp "init-bootstrap.el" "init.el"
fi
#+end_src

Multiple tools we use to support our development flow are based on Node.js.
We need to install those tools in our system below.

#+begin_src sh :tangle setup.sh
# Set Node.js version requirement based on Copilot usage. Update minimum versions as needed.
if [ "$ENABLE_COPILOT" = "true" ]; then
  REQUIRED_NODE_VERSION="22.0.0"  # GitHub Copilot requires Node.js 22.x or later
  echo -e "\033[1;33m[ Copilot enabled - Node.js 22.0.0+ required ]\033[0m"
else
  REQUIRED_NODE_VERSION="20.19.2"  # Standard requirement without Copilot.
  echo -e "\033[1;33m[ Standard setup - Node.js 20.19.2+ required ]\033[0m"
fi

check_node_version() {
  echo -e "\033[1;32m[ Checking Node.js Version ]\033[0m"

  if ! command -v node >/dev/null 2>&1; then
    echo -e "\033[1;31mError: Node.js is not installed. Please install it before running this script.\033[0m"
    exit 1
  fi

  CURRENT_NODE_VERSION=$(node -v | sed 's/v//')

  # Version comparison logic: checks if current version is less than required version
  if [ ! "$(printf '%s\n' "$REQUIRED_NODE_VERSION" "$CURRENT_NODE_VERSION" | sort -V | head -n1)" = "$REQUIRED_NODE_VERSION" ]; then
    echo -e "\033[1;31mError: You have Node.js version $CURRENT_NODE_VERSION, but we require at least version $REQUIRED_NODE_VERSION to proceed.\033[0m"
    echo "Please update Node.js before proceeding."
    exit 1
  fi

  echo -e "\033[1;32mNode.js $CURRENT_NODE_VERSION meets the requirement ($REQUIRED_NODE_VERSION).\033[0m"
}

install_nodejs_tools() {
  echo -e "\033[1;32m\n[ Installing Node.js tools used by Emacs packages ]\033[0m"

  local TOOLS_DIR="$HOME/.emacs.d/nodejs_tools"

  if [ ! -d "$TOOLS_DIR" ]; then
    echo "Error: Directory $TOOLS_DIR not found. Skipping npm install."
    return 1
  fi

  cd "$TOOLS_DIR" || exit 1
  rm -Rf node_modules
  npm install

  # Small hack for bash-language-server to work with lsp-mode
  echo "Applying bash-language-server symlink hack..."
  rm -Rf "$HOME/.emacs.d/.cache/lsp/npm/bash-language-server/"
  mkdir -p "$HOME/.emacs.d/.cache/lsp/npm/bash-language-server/bin/"
  ln -s "$TOOLS_DIR/node_modules/.bin/bash-language-server" "$HOME/.emacs.d/.cache/lsp/npm/bash-language-server/bin/bash-language-server"
}

check_node_version
install_nodejs_tools
#+end_src

** Interactive DO settings

IDO (Interactively DO things) replaces many minibuffer prompts with a
compact interactive matcher that narrows candidates as you type. These
options tune its behavior:

- ~ido-enable-flex-matching~: allow substring and flexible matching
(not only prefix matches). Type parts of a name in any order and IDO
will still find it.
- ~ido-everywhere~: use IDO's interface for most buffer/file
minibuffer prompts (where sensible), giving a consistent
completion experience across commands.
- ~(ido-mode 1)~: enable IDO globally.

IDO is built into Emacs, lightweight, and improves the speed of file
and buffer selection without external dependencies.

However, not all commands use IDO by default. The package
[[ido-completing-read+]] provides a more powerful interface for
completing read commands using IDO.

#+begin_src emacs-lisp
(setq ido-enable-flex-matching t) ; better string matching on search
(setq ido-everywhere t)           ; toggle use of Ido for all buffer/file reading
(ido-mode 1)

(use-package ido-completing-read+
  ;; "defer" is needed to prevent errors during initialization in some systems
  :defer t
  :config
  (ido-ubiquitous-mode 1))
#+end_src

* Emacs hacks

** Faster startup

A common startup speed-up is to disable the garbage collection during
Emacs initialization, and enable it back after it. The code below
temporarily raises ~gc-cons-threshold~ to an extremely large value and
clears file.

A common startup speed-up is to defer garbage collection and file-name
handler processing while Emacs initializes. The code below temporarily
raises ~gc-cons-threshold~ to an extremely large value and clears
file-name-handler-alist before init so GC cycles and file-handler
overhead are avoided during startup. It then restores the original
file-name-handler-alist and a reasonable gc-cons-threshold in an
emacs-startup-hook after initialization completes. Finally,
~inhibit-default-init~ prevents loading your environment's default
global settings together with your init file (adapted from
[[https://github.com/larstvei/dot-emacs/blob/main/init.org][the dot-emacs-repository]]).

#+begin_src emacs-lisp :tangle early-init.el
(let ((file-name-handler-alist-old file-name-handler-alist))
  (add-hook 'emacs-startup-hook
            (lambda ()
              (setq gc-cons-threshold (* 1024 1024 20))
              (setq file-name-handler-alist file-name-handler-alist-old)))
  (setq gc-cons-threshold most-positive-fixnum)
  (setq file-name-handler-alist nil))

(setq inhibit-default-init t)
#+end_src


** Resize issue on certain terminals

When moving a terminal window between monitors or resizing it quickly,
Emacs running in a tty can briefly see inconsistent size or DPI info.
That can make Emacs compute the wrong number of rows/columns and push
lines or UI elements off-screen even though the terminal already grew.

The root causes are timing and handshake differences between the
terminal emulator and Emacs (TERM or DPI changes and delayed resize
notifications). The terminal may update geometry after Emacs has
already calculated layout.

The workaround forces an immediate redisplay, a gentle recenter, and a
few retry attempts after short delays; as a last resort it re-applies
the frame size. These retries catch late-arriving terminal updates and
bring Emacs' view into alignment with the terminal once the emulator
finishes reporting geometry.

The code only runs for non-graphical (tty) sessions and uses safe
ignore-errors wrappers, so risk is low.

#+begin_src emacs-lisp
;; Resize fixes and logging (preserved)
(defun my/tty-resize-fix (&rest _args)
  "Robustly fix terminal/frame resize artifacts.
When running in a terminal, some resize events (DPI/monitor switch)
leave the UI in a bad state. Try several redisplay/recenter attempts
and a safe frame-size reapply as a fallback.

This is intentionally conservative (ignore-errors) and only runs when
display is non-graphical, so it is safe for GUI Emacs too."
  (ignore-errors
    (redisplay)

** ANSI color support in the magit process buffer

When running Git commands through Magit (e.g., hooks, pre-commit scripts), the output
is displayed in the *magit-process* buffer (accessible by pressing `$` in the Magit
status buffer). This buffer shows the raw output from Git commands. However, by
default, ANSI color codes in the output are not interpreted, so the output appears
with raw escape sequences instead of colored text.

There are two approaches to enable ANSI color support in the Magit process buffer:

*** Option 1: Official built-in solution (with delay)

The official way to enable ANSI colors is to set `magit-process-finish-apply-ansi-colors`.
However, this only applies colors after the Git command has finished executing. For
slow processes (like long-running hooks), you'll see the raw escape sequences until the
command completes, which can be distracting.

#+begin_example emacs-lisp
;; Official built-in solution - applies colors after command finishes
(setq magit-process-finish-apply-ansi-colors t)
#+end_example


*** Option 2: Real-time color application (recommended)

A better solution, suggested in [[https://github.com/magit/magit/issues/3549#issuecomment-1375023283][this GitHub comment]],
applies colors in real-time as the buffer is updated. This provides immediate visual
feedback without showing raw escape sequences during long-running commands. This is
the approach we use in our configuration:

#+begin_src emacs-lisp
;; Apply ANSI colors in real-time as the magit-process buffer is updated
(defun my/magit-color-buffer (proc &rest args)
  "Apply ANSI colors to the magit-process buffer in real-time."
  (with-current-buffer (process-buffer proc)
    (read-only-mode -1)
    (ansi-color-apply-on-region (point-min) (point-max))
    (read-only-mode 1)))

(advice-add 'magit-process-filter :after #'my/magit-color-buffer)
#+end_src

;; Helper: show faces used on the current line (interactive)
(defun my/show-faces-on-line ()
  "Collect and message the face symbols used on the current line.

Useful to inspect which faces are present (returns symbols or plists).
You can also use `M-: (face-at-point) RET` or `C-u C-x =` for more detail."
  (interactive)
  (let* ((beg (line-beginning-position))
         (end (line-end-position))
         (faces '()))
    (save-excursion
      (goto-char beg)
      (while (< (point) end)
        (let ((prop (get-text-property (point) 'face)))
          (cond
           ((symbolp prop) (push prop faces))
           ((listp prop) (dolist (el prop) (when (symbolp el) (push el faces))))))
        (forward-char 1)))
    (setq faces (delete-dups faces))
    (if faces
        (message "Faces on line: %s" faces)
      (message "No face text-properties on this line; try (face-at-point) or C-u C-x ="))))
#+end_src

** Code completion

Company (COMPLete ANY) provides in-buffer completion popups - automatic

** GitHub Copilot (Emacs 29+ only)

Official GitHub Copilot integration for Emacs. It provides AI-powered code
suggestions as you type. This configuration uses ~package-vc~, which is a
built-in package manager introduced in Emacs 29+ that can install packages
directly from Git repositories.

For older Emacs versions, you'll need to manually clone the repository.

**Installation Requirements:**
1. Node.js (handled by setup.sh)
2. Copilot Language Server (installed via nodejs_tools/package.json)

#+begin_src emacs-lisp
;; Install and configure Copilot using package-vc (Emacs 29+)
;; We are using package-vc-install below for compatibility with Emacs 29+. In
;; Emacs 30+, we could use `:vc (:fetcher github :repo "copilot-emacs/copilot.el")`
;; directly in use-package.
(when (fboundp 'package-vc-install)
  (unless (package-installed-p 'copilot)
    (package-vc-install "https://github.com/copilot-emacs/copilot.el"))

  (use-package copilot
    :ensure nil  ; Installed via package-vc, don't try MELPA
    :init
    ;; Disable indentation offset warnings - Copilot will use existing indentation
    ;; See https://github.com/copilot-emacs/copilot.el/issues/312#issuecomment-2729052774
    (setq copilot-indent-offset-warning-disable t)

    ;; Disable buffer size warnings - prevents "file size exceeds copilot-max-char" warnings for large files
    ;; Not working yet. See https://github.com/copilot-emacs/copilot.el/issues/313
    (setq copilot-max-char-warning-disabled t)

    :config
    ;; Configure Copilot to use our custom nodejs_tools installation
    (let ((copilot-server (expand-file-name "nodejs_tools/node_modules/.bin/copilot-language-server"
                                            user-emacs-directory))
          (node-binary (executable-find "node")))
      (cond
       ;; Check if our local installation exists and is executable
       ((and (file-executable-p copilot-server) node-binary)
        (setq copilot-server-executable copilot-server)
        (message "Copilot: Using local server at %s" copilot-server))

       ;; Fallback to system installation
       ((executable-find "copilot-language-server")
        (setq copilot-server-executable (executable-find "copilot-language-server"))
        (message "Copilot: Using system server"))

       ;; No server found
       (t
        (message "Copilot: No language server found. Run setup.sh to install locally.")
        (setq copilot-mode nil))))

    ;; Files to exclude from Copilot
    (defvar my/copilot-excluded-files
      '("\\.env\\(\\..*\\)?$"
        "\\.config$"
        "\\.cfg$"
        "secret"
        "credential"
        "^id_rsa"
        "\\.key$"
        "\\.log$"
        "\\.tmp$"
        "\\.ini$"
        "\\.txt$")
      "List of regex patterns for files to exclude from Copilot.")

    (defun my/copilot-kubernetes-sensitive-p ()
      "Check if current buffer contains Kubernetes sensitive content (Secrets or ConfigMaps)."
      (save-excursion
        (goto-char (point-min))
        (and (re-search-forward "^apiVersion:" nil t)
             (goto-char (point-min))
             (re-search-forward "^kind:\\s-*\\(Secret\\|ConfigMap\\)\\s-*$" nil t))))

    (defun my/copilot-excluded-file-p ()
      "Check if current file should be excluded from Copilot."
      (or
       ;; Check filename patterns
       (and buffer-file-name
            (let ((filename (file-name-nondirectory buffer-file-name)))
              (cl-some (lambda (pattern)
                         (string-match-p pattern filename))
                       my/copilot-excluded-files)))
       ;; Check directory patterns
       (and buffer-file-name
            (string-match-p "/\\(dist\\|build\\|vendor\\)/" buffer-file-name))
       ;; Check content patterns
       (my/copilot-kubernetes-sensitive-p)))

    (defun my/safe-copilot-mode ()
      "Enable copilot-mode with silent error handling, excluding sensitive files."
      (unless (my/copilot-excluded-file-p)
        (condition-case err
            (when (and copilot-server-executable
                       (file-executable-p copilot-server-executable))
              (copilot-mode 1))
          (error
           (message "Copilot mode activation failed. Check the *copilot events* buffer for details")
           (setq copilot-mode nil)))))

    :hook ((prog-mode . my/safe-copilot-mode)
           (text-mode . my/safe-copilot-mode)
           (markdown-mode . my/safe-copilot-mode)
           (yaml-mode . my/safe-copilot-mode)
           (json-mode . my/safe-copilot-mode)
           (sh-mode . my/safe-copilot-mode)
           (dockerfile-mode . my/safe-copilot-mode)
           (css-mode . my/safe-copilot-mode)
           (sql-mode . my/safe-copilot-mode)
           (conf-mode . my/safe-copilot-mode))
    :bind (("C-c c t" . copilot-mode)          ; Toggle copilot in buffer
           ("C-c c l" . copilot-login)         ; Login to copilot
           ("C-c c d" . copilot-diagnose)      ; Check copilot status
           :map copilot-completion-map
           ("C-g" . copilot-clear-overlay)     ; Clear suggestion
           ("M-p" . copilot-previous-completion)
           ("M-n" . copilot-next-completion)
           ("C-<tab>" . copilot-accept-completion)
           ("C-TAB" . copilot-accept-completion))))

** Code Formatting

*** Automatic code formatting with Apheleia

Apheleia is a lightweight Emacs package for automatic code formatting. It runs
external formatters (like Prettier, Black, shfmt, etc.) and replaces buffer text
with the formatted result asynchronously, so Emacs stays responsive. You can map
modes to formatters, and Apheleia will format files automatically on save or on
demand. This helps keep your codebase consistent and clean with minimal effort.

For Org mode source blocks, we enable =org-src-tab-acts-natively= so that
TAB indents according to the source block's language mode.

**** Usage

*Manual buffer formatting:*

Press =C-c f= (in any mode) to manually format the current buffer with Apheleia.

*Org source blocks:*

With =org-src-tab-acts-natively= enabled:
- TAB key works natively within source blocks (respects the language's indentation)
- Use =C-c '= to open source blocks in their native major mode (Apheleia will format on save there)
- Use =C-c f= to manually format the current buffer if needed

*Supported languages and formatters:*

The following languages are configured with their respective formatters:

- **Emacs Lisp** (=emacs-lisp-mode=, =lisp-interaction-mode=) → Built-in =lisp-indent=
- **JavaScript** (=js-mode=, =js-ts-mode=) → Prettier (local installation)
- **TypeScript** (=typescript-mode=, =typescript-ts-mode=, =tsx-ts-mode=) → Prettier (local installation)
- **Python** (=python-mode=, =python-ts-mode=) → Prettier with =@prettier/plugin-python=
- **JSON** (=json-mode=, =json-ts-mode=) → Prettier (local installation)
- **Web/HTML** (=web-mode=) → Prettier (local installation)

Note: Prettier is installed locally in =~/.emacs.d/nodejs_tools/= with the Python plugin.

*Adding new formatters:*

To add a new formatter, add it to =apheleia-formatters= and map it to the
appropriate mode in =apheleia-mode-alist=. For example:

#+begin_example
;; Add a new formatter
(setf (alist-get 'my-formatter apheleia-formatters)
      '("my-formatter-command" "--option" "value" file))

;; Map it to a mode
(setf (alist-get 'my-mode apheleia-mode-alist) 'my-formatter)
#+end_example

*** Kotlin

To enable IDE features for Kotlin, you need to install the Kotlin Language Server
(KLS) and configure Emacs to use it. There are two main ways to install it:

1. **Using SDKMAN** (recommended)

- **Install SDKMAN:** [https://sdkman.io/](https://sdkman.io/)
  - SDKMAN is a tool for managing parallel versions of multiple software development
    kits on Unix-based systems. We will use it to install the official Kotlin compiler
    and runtime.

- **Install Kotlin Language Server:**
  - This means you need to set up the Kotlin Language Server (KLS), which provides
    IDE features (like code completion, go-to-definition, etc.) for editors that
    support the Language Server Protocol (LSP). SDKMAN does not provide the
    language server—only the compiler.

- **Clone and build the language server:**
  - The Kotlin Language Server is not distributed as a prebuilt binary. We must
    clone its source code from GitHub and build it. This step downloads the source
    and compiles the server executable.

- **The server executable will be at:**
  - After building, the main executable for the language server will be located at:
    `server/build/install/server/bin/kotlin-language-server`
  - This is the file our LSP client (like Emacs with lsp-mode) will launch to provide
    Kotlin IDE features.

2. **Manual installation**

   - Download a release from:
     https://github.com/fwcd/kotlin-language-server/releases
   - Unpack and use the `bin/kotlin-language-server` executable.

Here we update our setup script snippet:

#+begin_src sh :tangle setup.sh
# Update the version for Kotlin below as needed:
KOTLIN_VERSION="2.2.21"
KOTLIN_LS_VERSION="1.3.13"

install_kls() {
  local KLS_TMP_DIR
  KLS_TMP_DIR=$(mktemp -d)
  local KLS_TARGET_DIR="$HOME/.emacs.d/lsp_language_servers/kotlin.ls"

  echo "Downloading prebuilt Kotlin Language Server (KLS)..."
  curl -L "https://github.com/fwcd/kotlin-language-server/releases/download/$KOTLIN_LS_VERSION/server.zip" -o "$KLS_TMP_DIR/kotlin-language-server.zip"

  echo "Extracting Kotlin Language Server..."
  rm -Rf "$KLS_TARGET_DIR" # Clean previous install
  mkdir -p "$KLS_TARGET_DIR"
  unzip -q "$KLS_TMP_DIR/kotlin-language-server.zip" -d "$KLS_TMP_DIR"
  mv "$KLS_TMP_DIR/server"/* "$KLS_TARGET_DIR/"
  rm -Rf "$KLS_TMP_DIR"

  echo -e "\033[1;32mKotlin Language Server installed to $KLS_TARGET_DIR\033[0m"
}

install_kotlin_sdkman() {
  echo -e "\033[1;32m\n[ Installing Kotlin Language Server (KLS) via SDKMAN ]\033[0m"

  sdk install kotlin "$KOTLIN_VERSION"

  local KOTLIN_HOME
  KOTLIN_HOME=$(sdk home kotlin "$KOTLIN_VERSION" 2>/dev/null)

  if [ -n "$KOTLIN_HOME" ]; then
    echo "Kotlin installed in $KOTLIN_HOME"
    install_kls
  else
    echo -e "\033[1;33mWarning: Could not determine Kotlin installation path. Skipping Kotlin Language Server installation.\033[0m"
  fi
}

install_kotlin_manual() {
  echo -e "\033[1;32m\n[ Installing Kotlin Language Server (KLS) Manually ]\033[0m"
  echo "SDKMAN not found. Installing Kotlin compiler from official sources..."

  local KOTLIN_DIR="$HOME/.kotlin"
  rm -Rfv "$KOTLIN_DIR" # Clean previous install
  mkdir -p "$KOTLIN_DIR"

  echo "Downloading Kotlin $KOTLIN_VERSION..."
  curl -L "https://github.com/JetBrains/kotlin/releases/download/v${KOTLIN_VERSION}/kotlin-compiler-${KOTLIN_VERSION}.zip" -o /tmp/kotlin.zip
  unzip -q /tmp/kotlin.zip -d "$KOTLIN_DIR"
  rm /tmp/kotlin.zip

  echo "Kotlin compiler installed to $KOTLIN_DIR/kotlinc"
  echo "Note: Add $KOTLIN_DIR/kotlinc/bin to your PATH manually."

  # Install Kotlin Language Server
  install_kls
}

if ! "$SKIP_KOTLIN"; then
  if command -v sdk >/dev/null 2>&1; then
    install_kotlin_sdkman
  else
    install_kotlin_manual
  fi
else
  echo -e "\033[1;33m\n[ Skipping Kotlin Language Server (KLS) as requested ]\033[0m"
fi
#+end_src

install_shellcheck() {
  echo -e "\033[1;32m\n[ Installing ShellCheck ]\033[0m"

  if ! command -v shellcheck >/dev/null 2>&1; then

    # 1. Check for Debian/Ubuntu (apt)
    if [ -f /etc/debian_version ] && command -v apt >/dev/null 2>&1; then
      echo "Using apt to install ShellCheck..."
      sudo apt update
      sudo apt install -y shellcheck

    # 2. Check for Fedora/RHEL (dnf)
    elif [ -f /etc/fedora-release ] || command -v dnf >/dev/null 2>&1; then
      echo "Using dnf to install ShellCheck (RHEL/Fedora)..."
      # dnf is generally available and doesn't require a preceding update like apt
      sudo dnf install -y ShellCheck

    # 3. Fallback/Manual install warning
    else
      echo -e "\033[1;33mWarning: Could not automatically install ShellCheck. Please install it manually using your OS package manager.\033[0m"
      echo "See: https://github.com/koalaman/shellcheck#installing"
    fi
  else
    echo "ShellCheck is already installed."
  fi
}

install_shellcheck

* Project management

Project management in Emacs is handled by the built-in `project` package, which provides
a unified interface for working with projects. To enhance the project management experience,
we can integrate Magit, a popular Git interface for Emacs, into the project switch commands

#+begin_src emacs-lisp
(use-package project
  :preface
  (defun my/treemacs-sync-with-project ()
    "Restrict Treemacs to display only the current project."
    (with-eval-after-load 'treemacs
      (when (project-current)
        (save-selected-window
          (save-current-buffer
            (treemacs-display-current-project-exclusively))))))

  :config
  (add-to-list 'project-switch-commands '(magit-project-status "Magit" ?m))

  ;; If running as a daemon, prevent 'project.el' from asking for a project root.
  ;; It should only prompt if run interactively (i.e., when you open emacsclient).
  (when (daemonp)
    (setq project-find-project-by-default nil))

  ;; Ignoring temporary/emacs files in projects
  (add-to-list 'project-vc-ignores "*~")
  (add-to-list 'project-vc-ignores ".#*~")
  (add-to-list 'project-vc-ignores "#*")
  (add-to-list 'project-vc-ignores ".#*")

  (add-hook 'project-switch-functions #'my/treemacs-sync-with-project)
  (add-hook 'find-file-hook #'my/treemacs-sync-with-project)
  (add-hook 'emacs-startup-hook #'my/treemacs-sync-with-project))
#+end_src

* PDF Tools

[[https://github.com/vedang/pdf-tools][PDF Tools]] makes a huge improvement on the built-in [[http://www.gnu.org/software/emacs/manual/html_node/emacs/Document-View.html][doc-view-mode]]! Removing
the =header-line-format= gives a very clean PDF-viewer; let's add that to a
key.

(declare-function pdf-loader-install "pdf-tools" nil)
(declare-function pdf-view-desired-image-size "pdf-view")
(declare-function pdf-view-create-page "pdf-view")
(declare-function pdf-util-frame-scale-factor "pdf-util")
(declare-function pdf-util-hexcolor "pdf-util")
(declare-function pdf-view-buffer-file-name "pdf-view")
(declare-function pdf-util-munch-file "pdf-util")

(declare-function image-mode-window-get "image-mode")
(declare-function image-set-window-hscroll "image-mode")
(declare-function image-set-window-vscroll "image-mode")

;; Emacs support library for PDF files
(use-package pdf-tools
  :defer t
  :mode "\\.pdf\\'"
  :bind (:map pdf-view-mode-map
              ("c" . (lambda ()
                       (interactive)
                       (if header-line-format
                           (setq header-line-format nil)
                         )))
              ("j" . pdf-view-next-line-or-next-page)
              ("k" . pdf-view-previous-line-or-previous-page))
  :config
  (unless (daemonp)
    (pdf-loader-install))
  (add-to-list 'revert-without-query ".pdf"))

* Description
Provides IDE capabilities for Java development using Eclipse JDTLS, ~lsp-java~,
JAL agent support, ~dap-mode~ debugging via a custom =compile_attach= provider,
and Google Java Format via Apheleia.

* Emacs Configuration
** Java Agent Loader (JAL)
**Java Agent Loader (JAL)** is a utility package I develop and maintain to
streamline the detection, configuration, and management of Java Agents within
your Java applications. Java Agents are special components that can instrument
Java bytecode at runtime, enabling advanced features such as monitoring,
profiling, code coverage analysis, security auditing, and more, without
modifying your application's source code.

With JAL, you can automatically discover and configure Java Agents for your
projects, eliminating the need for manual setup. This ensures your applications
are always instrumented with the necessary tools for observability, diagnostics,
or specialized runtime enhancements.

**Common examples of Java Agents include:**
- **Monitoring tools** (e.g., New Relic, AppDynamics, Java Flight Recorder)
- **Profilers** (e.g., YourKit, VisualVM)
- **Code coverage analyzers** (e.g., JaCoCo)
- **Security and tracing agents** (e.g., OpenTelemetry Java agent, Dynatrace)

In addition to that, while not a traditional Java Agent, **Lombok** is often
configured in a similar manner, using the `-javaagent` parameter in the JVM
options. This means Lombok is specified on the command line or in IDE
configurations as if it were a Java agent, even though it acts as an *annotation
processor* at compile time rather than as a runtime bytecode modifier.

JAL seamlessly integrates with popular build systems such as **Gradle** and
**Maven**, making agent management part of your standard build pipeline.
Additionally, it supports Java language servers like **LSP-java** and
**eglot-java**, ensuring agent configuration works smoothly during development
for in-editor tooling and code analysis.

JAL must be configured **before** ~lsp-java~.

  (defun cfg-lang/lsp-java-discover-runtimes ()
    "Discover SDKMAN! java versions and return them as a vector for lsp-java.

Maps SDKMAN version directories to JDT execution environment names
(e.g. `JavaSE-17'). When multiple patch versions of the same major
exist only the lexicographically latest one is kept. All discovered
runtimes are passed to jdtls; if jdtls does not recognise an environment
it emits an \"Invalid runtime\" warning which is intercepted by
`cfg-lang/lsp-java-invalid-runtime-advice' to show an actionable hint."
    (let ((sdk-dir (expand-file-name "~/.sdkman/candidates/java")))
      (when (file-exists-p sdk-dir)
        (let* ((dirs (seq-filter
                      (lambda (dir)
                        (and (file-directory-p dir)
                             (not (string-equal (file-name-nondirectory dir) "current"))))
                      (directory-files sdk-dir t "^[^.]")))
               (major->path (make-hash-table :test 'equal)))
          (dolist (path dirs)
            (let* ((dir-name (file-name-nondirectory path))
                   (major (when (string-match "^\\([0-9]+\\)" dir-name)
                            (string-to-number (match-string 1 dir-name)))))
              (when major
                (let ((existing (gethash major major->path)))
                  (when (or (null existing)
                            (string> dir-name (file-name-nondirectory existing)))
                    (puthash major path major->path))))))
          (let (runtime-list)
            (maphash (lambda (major path)
                       (let ((env-name (if (= major 8) "JavaSE-1.8" (format "JavaSE-%d" major))))
                         (push `(:name ,env-name :path ,path) runtime-list)))
                     major->path)
            (vconcat runtime-list))))))

  (setq lsp-java-configuration-runtimes (cfg-lang/lsp-java-discover-runtimes))

  ;; jdtls is the source of truth for supported execution environments.
  ;; When it sends back an "Invalid runtime" warning (meaning a JDK we passed
  ;; is newer than what this jdtls release knows about), intercept it and
  ;; append an actionable hint so upgrading jdtls is the obvious next step.
  (defun cfg-lang/lsp-java-invalid-runtime-advice (format-string &rest args)
    "Intercept jdtls \"Invalid runtime\" warnings and add an actionable hint."
    (let ((msg (apply #'format format-string args)))
      (when (string-match "Invalid runtime for \\(JavaSE-[0-9.]+\\)" msg)
        (message "lsp-java: '%s' is not supported by the installed jdtls." (match-string 1 msg)))))

  (advice-add 'lsp--warn :after #'cfg-lang/lsp-java-invalid-runtime-advice))

** m2e Compliance Workaround
~lsp-java~ uses the Eclipse JDT Language Server (=jdtls=), which delegates Maven
project import and POM processing to Maven Integration for Eclipse (=m2e=).
During import, =m2e= computes the effective POM, resolves dependencies, and
generates Eclipse project metadata -- such as =.classpath=, =.project=, and
=.settings= -- that =jdtls= consumes to build its project model and classpath.
Because =jdtls= relies on that generated metadata, any incorrect property
resolution performed by =m2e= (for example, resolving a property against a
parent POM instead of a child override) will propagate into the language server
as an incorrect Java compliance level or JRE container, resulting in missing
APIs, spurious diagnostics, and other incorrect language-server behavior.

When =m2e= evaluates Maven properties that use indirection (for example, when
=maven.compiler.source=, =maven.compiler.target= or =maven.compiler.release= are
defined in terms of another property such as =${project.build.java.target}=), it
can sometimes resolve the reference against the parent POM rather than a child
module's override. The result is generated Eclipse settings and workspace
metadata that claim an incorrect, older Java compliance level and place an older
JRE container on the module classpath (for example, =JavaSE-1.8=). That mismatch
causes language servers and editors to report missing APIs or incorrect
diagnostics.

This issue is reported at eclipse-m2e/m2e-core/issues/2156.

Solution implemented here (local workaround): after =m2e= finishes importing
projects (=jdtls= reports "Started"), the functions in this section read the
intended Java compliance value and rewrite the generated JDT workspace and
module files to match. Concretely, the code below:

- updates =.settings/org.eclipse.jdt.core.prefs= entries in the =jdtls=
  workspace metadata to set =org.eclipse.jdt.core.compiler.compliance=,
  =org.eclipse.jdt.core.compiler.source= and
  =org.eclipse.jdt.core.compiler.codegen.targetPlatform= to the resolved value;
- patches module =.classpath= entries that reference the =JRE_CONTAINER= so they
  point to the correct =JavaSE-<version>= container.

These changes are generic and apply to any Maven multi-module project where
property indirection (for example, a parent property =project.build.java.target=
and a child override) leads to a discrepancy between Maven's effective model and
the files =m2e= generates.

*Example:*

~Parent POM properties:~

#+begin_src xml :tangle no
<project.build.java.target>1.8</project.build.java.target>
<maven.compiler.source>${project.build.java.target}</maven.compiler.source>
#+end_xml

~Child POM override:~

#+begin_src xml :tangle no
<project.build.java.target>25</project.build.java.target>
#+end_src

(defun cfg-lang/clean-jdtls-project-files (&optional root)
  "Delete stale Eclipse/jdtls project files.
It deletes `.classpath', `.project', `.settings' and `.factorypath'.
ROOT defaults to the current `lsp-workspace-root' or `projectile-project-root'.
These files are regenerated by jdtls/m2e on reimport. Delete them when
jdtls shows a wrong Java compliance level (e.g. reports Java-8 errors
on a Java-25 project) because m2e cached stale settings."
  (interactive)
  (let* ((root (or root
                   (and (fboundp 'lsp-workspace-root) (lsp-workspace-root))
                   (and (fboundp 'projectile-project-root) (projectile-project-root))
                   (read-directory-name "Project root: ")))
         (patterns '(".classpath" ".project" ".settings" ".factorypath"))
         (files '()))
    (dolist (pat patterns)
      (let ((found (directory-files-recursively root (concat "\\`" (regexp-quote pat) "\\'") t)))
        (setq files (append files found))))
    (if (null files)
        (message "No Eclipse project files found under %s" root)
      (when (yes-or-no-p (format "Delete %d Eclipse project files under %s? " (length files) root))
        (dolist (f files)
          (if (file-directory-p f) (delete-directory f t) (delete-file f)))
        (message "Deleted %d Eclipse project files. Restart LSP to reimport." (length files))))))

(defun cfg-lang/clean-jdtls-full (&optional root)
  "Full jdtls cleanup: delete workspace cache AND stale Eclipse project files.
Use when jdtls shows wrong Java compliance or persistent stale diagnostics.
ROOT is the project root to clean; if nil, prompts."
  (interactive)
  (cfg-lang/clean-jdtls-project-files root)
  (when (fboundp 'cfg-lang/clean-lsp-workspace-cache)
    (cfg-lang/clean-lsp-workspace-cache)))

(defun cfg-lang/jdtls--extract-pom-property (name)
  "Extract a literal property value for NAME from the current buffer's POM.
Returns nil if the property is not found or is a property reference."
  (save-excursion
    (goto-char (point-min))
    (when (re-search-forward (format "<%s>\\([^$<]+\\)</%s>" (regexp-quote name) (regexp-quote name)) nil t)
      (string-trim (match-string 1)))))

(defun cfg-lang/jdtls--extract-pom-property-raw (name)
  "Extract a raw property value (including ${refs}) for NAME from the current buffer."
  (save-excursion
    (goto-char (point-min))
    (when (re-search-forward (format "<%s>\\([^<]+\\)</%s>" (regexp-quote name) (regexp-quote name)) nil t)
      (string-trim (match-string 1)))))

(defun cfg-lang/jdtls--detect-maven-java-version (root)
  "Detect the Java version from Maven compiler settings in ROOT.
Reads `maven.compiler.release', falling back to `maven.compiler.source',
then `maven.compiler.target'. Returns the version string (e.g. \"25\")
or nil."
    (let ((pom (expand-file-name "pom.xml" root)))
    (when (file-exists-p pom)
      (with-temp-buffer
        (insert-file-contents pom)
        (or (cfg-lang/jdtls--extract-pom-property "maven.compiler.release")
            (cfg-lang/jdtls--extract-pom-property "maven.compiler.source")
            (cfg-lang/jdtls--extract-pom-property "maven.compiler.target")
            ;; Try resolving the property indirection one level
            (let ((prop-ref (cfg-lang/jdtls--extract-pom-property-raw "maven.compiler.release")))
              (when (and prop-ref (string-match "\\${\\(.+\\)}" prop-ref))
                (cfg-lang/jdtls--extract-pom-property (match-string 1 prop-ref)))))))))

(defun cfg-lang/jdtls--write-compliance-prefs (dir java-version)
  "Write `.settings/org.eclipse.jdt.core.prefs' in DIR with JAVA-VERSION."
  (let* ((settings-dir (expand-file-name ".settings" dir))
         (prefs-file (expand-file-name "org.eclipse.jdt.core.prefs" settings-dir))
         (content (format "\
eclipse.preferences.version=1
org.eclipse.jdt.core.compiler.codegen.methodParameters=generate
org.eclipse.jdt.core.compiler.codegen.targetPlatform=%s
org.eclipse.jdt.core.compiler.compliance=%s
org.eclipse.jdt.core.compiler.problem.enablePreviewFeatures=disabled
org.eclipse.jdt.core.compiler.problem.forbiddenReference=warning
org.eclipse.jdt.core.compiler.problem.reportPreviewFeatures=ignore
org.eclipse.jdt.core.compiler.processAnnotations=enabled
org.eclipse.jdt.core.compiler.release=enabled
org.eclipse.jdt.core.compiler.source=%s
" java-version java-version java-version)))
    (make-directory settings-dir t)
    (write-region content nil prefs-file)))

(defun cfg-lang/jdtls--fix-classpath-jre (dir env-name)
  "Set the JRE container in DIR/.classpath to ENV-NAME.
This is useful when m2e generates `.classpath' with another JRE (e.g.,
JavaSE-1.8) due to a property indirection bug (see
https://github.com/eclipse-m2e/m2e-core/issues/2156 for details). The
JRE container determines which class library is on the build path, so
even with correct compliance settings, APIs like List.of() are missing
if the container points to a version like JavaSE-1.8, for example."
  (let ((classpath-file (expand-file-name ".classpath" dir)))
    (when (file-exists-p classpath-file)
      (with-temp-buffer
        (insert-file-contents classpath-file)
        (when (re-search-forward "JRE_CONTAINER/org\\.eclipse\\.jdt\\.internal\\.debug\\.ui\\.launcher\\.StandardVMType/JavaSE-[0-9.]+" nil t)
          (let ((old (match-string 0))
                (new (format "JRE_CONTAINER/org.eclipse.jdt.internal.debug.ui.launcher.StandardVMType/%s" env-name)))
            (unless (string= old new)
              (goto-char (point-min))
              (while (search-forward old nil t) (replace-match new t t))
              (write-region (point-min) (point-max) classpath-file))))))))

(defun cfg-lang/jdtls-fix-m2e-compliance ()
  "Fix m2e setting the wrong Java compliance for Maven projects.
m2e in jdtls 1.57 does not resolve `maven.compiler.release' (or
`maven.compiler.source'/`target') correctly when the property uses
indirection through a parent POM. It falls back to the parent's default
\\(often Java 1.8) even though the child overrides the property to a higher
version. This function reads the effective `maven.compiler.release' (or
`source') from the project POM and writes the correct compliance to each
module's `.settings/org.eclipse.jdt.core.prefs'. jdtls picks up project-
directory settings with higher priority than its workspace metadata, so
this overrides the wrong m2e-generated values."
  (interactive)
  (let* ((root (or (and (fboundp 'lsp-workspace-root) (lsp-workspace-root))
                   (and (fboundp 'projectile-project-root) (projectile-project-root))
                   (read-directory-name "Project root: ")))
         (java-version (cfg-lang/jdtls--detect-maven-java-version root)))
    (if (null java-version)
        (message "Could not detect Java version from Maven for %s" root)
      (let ((count 0))
        ;; Write .settings for each submodule that has a src/main/java
        (dolist (pom (directory-files-recursively root "\\`pom\\.xml\\'"))
          (let ((mod-dir (file-name-directory pom)))
            (when (or (file-directory-p (expand-file-name "src/main/java" mod-dir))
                      (string= (file-truename (expand-file-name root))
                               (file-truename mod-dir)))
              (cfg-lang/jdtls--write-compliance-prefs mod-dir java-version)
              (setq count (1+ count)))))
        (message "Wrote Java %s compliance to %d module(s) under %s. Restart LSP to apply."
                 java-version count root)))))

(defun cfg-lang/jdtls--fix-compliance-after-import (workspace status)
  "Advice :after `lsp-java--language-status-callback'.

Advises jdtls's `language/status' callback to detect when jdtls reports
type=\"Started\" (meaning m2e has finished importing the project). At that
point, m2e has written its incorrect `.settings' files (e.g., defaulting to
`compliance=1.8').

This function overwrites those settings files with the correct Java version
resolved directly from the POM in memory, then notifies jdtls via
`workspace/didChangeWatchedFiles' to force a reload.

Runs on every \"Started\" event (including after rebuild/restart) because
m2e re-imports and overwrites `.settings' each time. This approach ensures
the POM is never modified on disk.

WORKSPACE is the lsp workspace, STATUS is the notification payload."
  (when-let* ((type (if (hash-table-p status) (gethash "type" status) (plist-get status :type)))
              (_started (string= type "Started"))
              (root (lsp--workspace-root workspace))
              (pom (expand-file-name "pom.xml" root))
              (_has-pom (file-exists-p pom))
              (java-version (cfg-lang/jdtls--detect-maven-java-version root)))
    (let ((count 0)
          (env-name (if (string= java-version "8") "JavaSE-1.8" (format "JavaSE-%s" java-version))))
      ;; 1. Write .settings in every module that has a pom.xml
      (dolist (mod-pom (directory-files-recursively root "\\`pom\\.xml\\'"))
        (let ((mod-dir (file-name-directory mod-pom)))
          (cfg-lang/jdtls--write-compliance-prefs mod-dir java-version)
          (setq count (1+ count))))
      ;; 1b. Patch every .classpath found anywhere under the project root.
      ;; m2e writes .classpath files into dirs co-located with pom.xml AND
      ;; occasionally into dirs without a pom.xml (generated-source dirs,
      ;; synthetic Eclipse sub-projects). Scanning for .classpath directly
      ;; covers both cases in a single pass with no redundancy.
      (dolist (cp-file (directory-files-recursively root "\\`\\.classpath\\'"))
        (cfg-lang/jdtls--fix-classpath-jre (file-name-directory cp-file) env-name))
      ;; 2. Overwrite the jdtls workspace metadata .settings AND .classpath
      (let ((ws-projects (expand-file-name ".metadata/.plugins/org.eclipse.core.resources/.projects" lsp-java-workspace-dir)))
        (when (file-directory-p ws-projects)
          (dolist (proj-dir (directory-files ws-projects t "^[^.]"))
            (when (file-directory-p proj-dir)
              (cfg-lang/jdtls--write-compliance-prefs proj-dir java-version)
              (cfg-lang/jdtls--fix-classpath-jre proj-dir env-name)))))
      ;; 3. Overwrite the global workspace JDT prefs
      (let ((global-prefs-dir (expand-file-name ".metadata/.plugins/org.eclipse.core.runtime/.settings" lsp-java-workspace-dir)))
        (when (file-directory-p global-prefs-dir)
          (cfg-lang/jdtls--write-compliance-prefs (file-name-directory global-prefs-dir) java-version)))
      ;; 4. Notify jdtls about the changes via workspace/didChangeWatchedFiles
      (with-lsp-workspace workspace
        (let (changes)
          (dolist (mod-pom (directory-files-recursively root "\\`pom\\.xml\\'"))
            (let* ((mod-dir (file-name-directory mod-pom))
                   (prefs (expand-file-name ".settings/org.eclipse.jdt.core.prefs" mod-dir)))
              (when (file-exists-p prefs)
                (push (list :uri (lsp--path-to-uri prefs) :type 2) changes))))
          ;; Notify about ALL .classpath files anywhere under the project root --
          ;; deep scan so we catch files not co-located with a pom.xml too.
          (dolist (cp-file (directory-files-recursively root "\\`\\.classpath\\'"))
            (push (list :uri (lsp--path-to-uri cp-file) :type 2) changes))
          ;; Also notify about .classpath changes in workspace metadata
          (let ((ws-projects (expand-file-name
                              ".metadata/.plugins/org.eclipse.core.resources/.projects"
                              lsp-java-workspace-dir)))
            (when (file-directory-p ws-projects)
              (dolist (proj-dir (directory-files ws-projects t "^[^.]"))
                (let ((cp (expand-file-name ".classpath" proj-dir)))
                  (when (file-exists-p cp)
                    (push (list :uri (lsp--path-to-uri cp) :type 2) changes))))))
          (when changes
            (lsp-notify "workspace/didChangeWatchedFiles"
                        (list :changes (apply #'vector changes))))))
      (message "m2e compliance fix: wrote Java %s (%s) to %d module(s) + workspace metadata under %s"
               java-version env-name count root))))

*** DAP Java: =compile_attach= helpers
The Eclipse JDT language server, when told to =launch= with
=integratedTerminal=, builds the java command with =-agentlib:jdwp=...server=n=:
the debug adapter listens and the JVM connects to it. This model is sent via a
=runInTerminal= DAP reverse-request, and none of the standard dap-mode hooks can
intercept it before the connection model is agreed upon.

The solution is to replace the =launch= flow entirely with =compile_attach=:
Emacs starts the JVM itself with =server=y= (the JVM listens), then the debug
adapter connects to it as a client. This also allows =vmArgs=, =args=, and =env=
from =launch.json= to be forwarded correctly.

Maven/Gradle compile commands, and wait for the JDWP listen line before the
adapter attaches.

  "Convert an ENV map from launch.json to an alist for dap-mode.

  (cond
   ((null env) nil)
   ((hash-table-p env)
    (let (result)
      (maphash (lambda (k v) (push (cons k v) result)) env)

   ((listp env)

             collect (cons (if (keywordp k)
                               (substring (symbol-name k) 1)
                             (format "%s" k))
                           v)))
   (t nil)))

(defun cfg-lang/dap-java--wait-for-jdwp (launch-args)
  "Wait until the compile_attach JVM in LAUNCH-ARGS is accepting JDWP.

probe that disconnects without completing JDWP's handshake makes the JVM
reject the real debug adapter connection."
  (let* ((port (plist-get launch-args :port))
         (buffer (get-buffer (format " * %s log*"
                                     (plist-get launch-args :name))))

         (deadline (+ (float-time) 30)))

                 (with-current-buffer buffer
                   (save-excursion
                     (goto-char (point-min))
                     (search-forward pattern nil t))))
      (user-error "Java JVM did not open JDWP port %s within 30 seconds" port))))

*** DAP Java: =compile_attach= session builder
Builds the attach session plist: resolve classpath via jdtls, start the JVM with
=server=y=, obtain a debug-adapter port, and hand dap-mode an attach config. The
debug provider routes terminal launches through this path.

#+begin_src emacs-lisp
(defun cfg-lang/dap-java--build-compile-attach (conf)
  "Build a compile_attach session plist from CONF.
Implements server=y: the JVM opens a debug socket and the debug
adapter connects to it. This avoids the default server=n path
used by JDT for launch+integratedTerminal configurations.

Keys read from CONF:
  :vmArgs / :vmargs    -- JVM flags merged with compat flags
  :args                -- program arguments after the main class
  :env                 -- environment variables (hash-table or plist)
  :mainClass           -- fully qualified main class name
  :projectName         -- Eclipse project name
  :cwd                 -- project working directory (used to find jdtls)
  :dap-compilation     -- optional shell command to run before attaching
  :dap-compilation-dir -- working directory for the build command

CONF is the launch configuration plist from the launch.json entry."
  (let* (;; Use mainClass and projectName directly from conf.
         ;; dap-java--populate-launch-args is intentionally bypassed: it
         ;; calls (lsp-find-workspace 'jdtls) internally without a path
         ;; arg, which falls back to the current buffer's LSP server when
         ;; called from a non-Java buffer, causing a
         ;; workspace/executeCommand error.
         (main-class    (or (plist-get conf :mainClass)
                            (user-error
                             "No :mainClass in launch configuration")))
         (project-name  (or (plist-get conf :projectName)
                            (user-error
                             "No :projectName in launch configuration")))
         (cwd           (or (plist-get conf :cwd) (lsp-java--get-root)))
         ;; Find the jdtls workspace using the project cwd as the lookup
         ;; key. lsp-find-workspace with a path uses
         ;; lsp-find-session-folder, which searches registered workspace
         ;; roots -- reliable even when called from a non-Java buffer.
         ;; Falls back to any jdtls workspace in the session if the path
         ;; lookup fails (e.g. if cwd is a subdirectory not cached yet).
         (jdtls-ws      (or (lsp-find-workspace 'jdtls cwd)
                            (lsp-find-workspace 'jdtls)
                            (user-error
                             (concat "jdtls is not running for %s. "
                                     "Open a Java file first")
                             cwd)))
         ;; Resolve the classpath via jdtls using the explicit workspace.
         ;; If jdtls's debug plugin is still initializing (e.g. right
         ;; after a failed session) this command may fail; the error
         ;; message instructs the user to wait and retry.
         ;; resolveClasspath returns [modulepaths, classpaths] -- a JSON array
         ;; that lsp-mode may decode as either a list or a vector depending
         ;; on the active JSON parser. `cl-second' (= `cadr') only works on
         ;; lists; use `seq-elt' which handles both.
         ;; Upstream dap-java.el uses index 1 for :classPaths (classpaths are
         ;; the second element). Validate with sequencep to catch cases where
         ;; the debug plugin is not yet loaded and returns a bare number or nil
         ;; instead of a string array. Fall back to index 0 for environments
         ;; where the order differs (e.g. older plugin versions).
         ;; Use lsp-request-async + accept-process-output for the same reason
         ;; as startDebugSession: lsp-request / sit-for returns immediately
         ;; when keyboard input is pending (the F5 keypress), handing back the
         ;; outgoing request plist (:jsonrpc "2.0" ...) instead of the actual
         ;; classpath array.  accept-process-output drains LSP output regardless
         ;; of pending keyboard events.
         (cp-raw        (let (result done)
                          (with-lsp-workspace jdtls-ws
                            (lsp-request-async
                             "workspace/executeCommand"
                             (list :command "vscode.java.resolveClasspath"
                                   :arguments (vector main-class project-name))
                             (lambda (res) (setq result res done t))
                             :error-handler
                             (lambda (err)
                               (message "DAP Java: resolveClasspath error: %S" err)
                               (setq done t))
                             :mode 'detached))
                          (let ((deadline (+ (float-time) 30)))
                            (while (and (not done) (< (float-time) deadline))
                              (accept-process-output nil 0.1)))
                          result))
         (classpaths    (let* ((arr1 (and (sequencep cp-raw)
                                          (> (length cp-raw) 1)
                                          (seq-elt cp-raw 1)))
                               (arr0 (and (sequencep cp-raw)
                                          (> (length cp-raw) 0)
                                          (seq-elt cp-raw 0)))
                               (lst (or (and (sequencep arr1)
                                             (cfg-lang/dap-java--normalize-to-list arr1))
                                        (and (sequencep arr0)
                                             (cfg-lang/dap-java--normalize-to-list arr0)))))
                          (or lst
                              (user-error
                               (concat "Cannot resolve classpath for %s "
                                       "(resolveClasspath returned: %S). "
                                       "Ensure the Java debug plugin bundle "
                                       "is loaded (check `lsp-java-bundles') "
                                       "and that jdtls has finished indexing")
                               main-class cp-raw))))
         (vmargs-str    (cfg-lang/dap-java--merge-vmargs conf))
         (prog-args-str (cfg-lang/dap-java--normalize-prog-args conf))
         (env-alist     (cfg-lang/dap-java--env-to-alist
                         (or (plist-get conf :env)
                             (when (hash-table-p conf) (gethash "env" conf)))))
         (port          (dap--find-available-port))
         ;; The JVM listens on PORT (server=y). Use localhost:PORT form
         ;; explicitly: Java 9+ changed the default binding for bare-port
         ;; addresses and some versions refuse to accept connections without
         ;; the explicit host. Do NOT use quiet=y here so that JDWP errors
         ;; are visible in the compilation log for troubleshooting.
         (jdwp-arg
          (format
           "-agentlib:jdwp=transport=dt_socket,server=y,suspend=y,address=localhost:%d"
           port))
         ;; Reference the classpath via an env variable to avoid shell
         ;; quoting issues when the classpath contains spaces.
         (cp-var (format dap-java--var-format "CLASSPATH_ARGS"))
         ;; Build the full java invocation. seq-filter removes empty
         ;; tokens so no stray spaces appear when args are absent.
         (java-command
          (string-trim
           (mapconcat
            #'identity
            (seq-filter (lambda (s) (not (string-empty-p s)))
                        (list dap-java-java-command
                              vmargs-str jdwp-arg
                              "-cp" cp-var
                              main-class prog-args-str))
            " ")))
         ;; Merge the classpath env var with application env vars from conf.
         (env-variables
          (append
           (list (cons "CLASSPATH_ARGS"
                       (s-join dap-java--classpath-separator classpaths)))
           env-alist))
         ;; Start the JDT debug adapter synchronously and capture its port.
         ;; lsp-send-execute-command delegates to lsp-request, which in Emacs
         ;; 29+ uses (sit-for 0.01) to wait for the response.  sit-for returns
         ;; immediately when keyboard input is pending (e.g. the F5 keypress
         ;; that triggered this call is still in the event queue), so the
         ;; response is never read and lsp-request returns the outgoing
         ;; request plist instead of the port integer -- causing
         ;; dap--open-network-stream to receive a plist where it expects a
         ;; string.  Using lsp-request-async with accept-process-output avoids
         ;; this: accept-process-output is specifically designed to drain
         ;; process output regardless of pending keyboard input.
         (debug-adapter-port
          (let (result done)
            (with-lsp-workspace jdtls-ws
              (lsp-request-async
               "workspace/executeCommand"
               (list :command "vscode.java.startDebugSession")
               (lambda (res) (setq result res done t))
               :error-handler
               (lambda (err)
                 (message "DAP Java: startDebugSession error: %S" err)
                 (setq done t))
               :mode 'detached))
            (let ((deadline (+ (float-time) 30)))
              (while (and (not done) (< (float-time) deadline))
                (accept-process-output nil 0.1)))
            (or result
                (user-error
                 (concat "vscode.java.startDebugSession did not return a port. "
                         "Ensure the Java debug plugin bundle is loaded "
                         "(check `lsp-java-bundles') and that jdtls has "
                         "finished indexing"))))))
    (message "DAP Java (compile_attach): %s:%s port=%d"
             project-name main-class port)
    (let* ((base-conf
            (dap-java--populate-attach-args
             (list :type              "java"
                   :request           "attach"
                   :hostName          "localhost"
                   :projectName       project-name
                   :host              "localhost"
                   ;; :port is the JVM's JDWP port.  dap-mode removes
                   ;; :debugServer from the plist before forwarding the
                   ;; attach request to the JDT debug adapter, so the
                   ;; adapter relies on :port to know where to connect.
                   ;; Do NOT add :wait-for-port here: dap--wait-for-port
                   ;; makes a raw TCP probe to :port (the JDWP socket);
                   ;; that bare connection triggers a failed JDWP
                   ;; handshake which can resume the JVM early and cause
                   ;; ClassNotFoundException before the debugger attaches.
                   ;; The JDT debug adapter has its own JDWP connection
                   ;; retry logic; the JVM will not run until it attaches
                   ;; (suspend=y).
                   :port              port
                   :program-to-start  java-command
                   :environment-variables env-variables
                   :startup-function  #'cfg-lang/dap-java--wait-for-jdwp
                   ;; Forward the optional build step from launch.json.
                   ;; If absent, auto-detect Maven or Gradle from the
                   ;; top-level workspace root (not cwd, which may be a
                   ;; submodule). Using lsp--workspace-root ensures we
                   ;; always compile the root project.
                   :dap-compilation
                   (or (plist-get conf :dap-compilation)
                       (when (hash-table-p conf)
                         (gethash "dap-compilation" conf))
                       (cfg-lang/dap-java--default-compilation-command
                        (lsp--workspace-root jdtls-ws)))
                   :dap-compilation-dir
                   (or (plist-get conf :dap-compilation-dir)
                       (when (hash-table-p conf)
                         (gethash "dap-compilation-dir" conf))
                       (lsp--workspace-root jdtls-ws))
                   ;; Debug adapter port obtained synchronously above.
                   ;; dap-mode connects here; the adapter then connects
                   ;; to the JVM via JDWP on :port above.
                   :debugServer       debug-adapter-port
                   :__sessionId       (number-to-string (float-time))))))
      base-conf)))

*** DAP Java: unit test runners
Safe replacements for upstream ~dap-java~ test commands. They avoid synchronous
=lsp-request= races, validate classpath response shapes, compile test sources

(defun cfg-lang/dap-java--resolve-test-classpath (test-class-name)

briefly returns a non-array response (a bare number or nil, e.g. while

around in `cfg-lang/dap-java--build-compile-attach'. Uses `lsp-request-async'
+ `accept-process-output' for the same reason as there (a synchronous
`lsp-request' can return early when keyboard input is pending), and
validates the response shape with `sequencep' before joining, falling
back to index 0 if the classpath is not at index 1."

                       (user-error "jdtls is not running. Open a Java file first")))
         (cp-raw (let (result done)
                   (with-lsp-workspace jdtls-ws
                     (lsp-request-async
                      "workspace/executeCommand"
                      (list :command "vscode.java.resolveClasspath"
                            :arguments (vector test-class-name nil))
                      (lambda (res) (setq result res done t))
                      :error-handler
                      (lambda (err)
                        (message "DAP Java: resolveClasspath error: %S" err)
                        (setq done t))
                      :mode 'detached))
                   (let ((deadline (+ (float-time) 30)))
                     (while (and (not done) (< (float-time) deadline))
                       (accept-process-output nil 0.1)))
                   result))
         (arr1 (and (sequencep cp-raw) (> (length cp-raw) 1) (seq-elt cp-raw 1)))
         (arr0 (and (sequencep cp-raw) (> (length cp-raw) 0) (seq-elt cp-raw 0)))
         (lst (or (and (sequencep arr1) (cfg-lang/dap-java--normalize-to-list arr1))
                  (and (sequencep arr0) (cfg-lang/dap-java--normalize-to-list arr0)))))
    (or lst
        (user-error
         (concat "Cannot resolve classpath for %s "
                 "(resolveClasspath returned: %S). "
                 "Ensure the Java debug plugin bundle is loaded "
                 "(check `lsp-java-bundles') and that jdtls has "
                 "finished indexing")
         test-class-name cp-raw))))

(defun cfg-lang/dap-java--default-test-compilation-command (root)
  "Auto-detect the Maven/Gradle *test* compile command for ROOT.
Companion to `cfg-lang/dap-java--default-compilation-command' (which only
builds main sources). Running or debugging a JUnit test happens in a
separate `java' process invoking
`junit-platform-console-standalone.jar', which only ever sees whatever
Maven/Gradle already wrote to disk (target/test-classes or
build/classes/test). `lsp-java-autobuild-enabled' is deliberately
off (see the `lsp-java' :init block) so that jdtls never writes its own
class files there and Maven/Gradle remains the sole authority -- but
that also means jdtls never compiles test sources either. Without this
step, an edited or newly added test method silently runs against a stale
or missing .class file, surfacing as \"failed to discover tests\"
instead of a normal compile error."
  (cond
   ((file-exists-p (expand-file-name "pom.xml" root))
    "mvn -q test-compile")
   ((or (file-exists-p (expand-file-name "build.gradle" root))
        (file-exists-p (expand-file-name "build.gradle.kts" root)))
    "gradle -q compileTestJava")
   (t
    (message "DAP Java: no pom.xml or build.gradle found in %s; skipping test compile step" root)
    nil)))

(defun cfg-lang/dap-java--test-class-relative-path (test-file)
  "Return (MODULE-ROOT . PKG-PATH) locating TEST-FILE's compiled class.
MODULE-ROOT is the nearest directory above TEST-FILE containing pom.xml,
build.gradle, or build.gradle.kts. PKG-PATH is TEST-FILE's path relative
to MODULE-ROOT with the leading src/test/java/ stripped and the .java
extension removed -- i.e. the same relative path javac writes the
compiled .class under (target/test-classes/ for Maven,
build/classes/java/test/ for Gradle). Returns nil when TEST-FILE is not
under a recognised src/test/java layout or no module root is found."
  (-when-let* ((module-root (locate-dominating-file
                             test-file
                             (lambda (dir)
                               (or (file-exists-p (expand-file-name "pom.xml" dir))
                                   (file-exists-p (expand-file-name "build.gradle" dir))
                                   (file-exists-p (expand-file-name "build.gradle.kts" dir))))))
              (rel (file-relative-name test-file module-root))
              (_ (string-prefix-p "src/test/java/" rel)))
    (cons module-root
          (s-chop-suffix ".java" (s-chop-prefix "src/test/java/" rel)))))

(defun cfg-lang/dap-java--candidate-test-class-files (test-file)
  "Return the Maven and Gradle compiled .class candidates for TEST-FILE.
Built from `cfg-lang/dap-java--test-class-relative-path'. Neither candidate is
required to already exist: `cfg-lang/dap-java--compiled-test-class-file' uses
this to check what is already on disk, and
`cfg-lang/dap-java--run-unit-test-command' embeds both paths in a shell
snippet that probes for whichever exists once compilation has run.
Returns nil when `cfg-lang/dap-java--test-class-relative-path' does."
  (-when-let ((module-root . pkg-path) (cfg-lang/dap-java--test-class-relative-path test-file))
    (list (expand-file-name (concat "target/test-classes/" pkg-path ".class") module-root)
          (expand-file-name (concat "build/classes/java/test/" pkg-path ".class") module-root))))

(defun cfg-lang/dap-java--compiled-test-class-file (test-file)
  "Return TEST-FILE's already-compiled .class path, or nil.
The first of `cfg-lang/dap-java--candidate-test-class-files' that exists on
disk, or nil if neither does (or TEST-FILE's layout is not recognised)
-- callers must treat nil as \"unknown\", not \"unchanged\"."
  (-first #'file-exists-p (cfg-lang/dap-java--candidate-test-class-files test-file)))

(defun cfg-lang/dap-java--test-needs-compile-p (test-file)
  "Return non-nil when TEST-FILE is newer than its compiled .class.
Failsafe against recompiling (running Maven/Gradle test-compile, see
`cfg-lang/dap-java--default-test-compilation-command') on every test run even
when nothing changed. Defaults to t (recompile) whenever
`cfg-lang/dap-java--compiled-test-class-file' cannot locate the compiled class
-- an unrecognised project layout must never be mistaken for \"already
up to date\", since that would silently reintroduce the stale-.class bug
this compile step exists to fix."
  (let ((class-file (cfg-lang/dap-java--compiled-test-class-file test-file)))
    (or (null class-file)
        (file-newer-than-file-p test-file class-file))))

(defun cfg-lang/dap-java--method-selector-shell-snippet (test-file class-name method-name)
  "Return a shell snippet exporting TEST_SELECTOR for METHOD-NAME.
JUnit Platform Console's bare \"CLASS-NAME#METHOD-NAME\" method selector
only resolves to a zero-argument method: for a `@ParameterizedTest' (or
any test method that takes arguments), resolution fails with \"Could not
find method with name ...\" even though the method exists and is
compiled, because the selector's reflection lookup has no parameter
types to match against.

The returned snippet looks up METHOD-NAME's parameter types with `javap'
against whichever of `cfg-lang/dap-java--candidate-test-class-files' exists
once the compile step above has actually run (this must happen at
shell-execution time, not here in Lisp, since a first-time compile means
neither candidate class file exists yet), and sets TEST_SELECTOR to
\"CLASS-NAME#METHOD-NAME(param, types)\" when found -- matching the
parameter-type format `javap -p' already prints, which is also the
format JUnit's method selector expects. Falls back to the bare
\"CLASS-NAME#METHOD-NAME\" (the previous, still-correct behaviour for
zero-argument test methods) when no class file or matching method line
can be found."
  (let ((selector (concat class-name "#" method-name))
        (candidates (cfg-lang/dap-java--candidate-test-class-files test-file)))
    (format "TEST_SELECTOR=%s
for __cf in %s; do
  if [ -f \"$__cf\" ]; then
    __line=$(javap -p \"$__cf\" 2>/dev/null | grep -E \"[ .]%s\\(\" | head -1)
    if [ -n \"$__line\" ]; then
      __params=$(echo \"$__line\" | sed -E 's/.*%s\\(([^)]*)\\).*/\\1/')
      TEST_SELECTOR=%s\"($__params)\"
    fi
    break
  fi
done
"
            (shell-quote-argument selector)
            (mapconcat #'shell-quote-argument candidates " ")
            method-name
            method-name
            (shell-quote-argument selector))))

(defun cfg-lang/dap-java--run-unit-test-command (runner dwim?)
  "Safe replacement for upstream `dap-java--run-unit-test-command'.
RUNNER is the test executor. DWIM? when t tries to run the surrounding
method, otherwise the surrounding test class. Classpath resolution goes
through `cfg-lang/dap-java--resolve-test-classpath' instead of the crash-prone
synchronous call in the upstream version, and a Maven/Gradle
test-compile step (see `cfg-lang/dap-java--default-test-compilation-command')
is prepended so the runner never executes against stale .class files --
unless `cfg-lang/dap-java--test-needs-compile-p' finds the compiled .class is
already newer than the test source, in which case the compile step is
skipped entirely. The build runs at the reactor root
\(`lsp--workspace-root'), not the buffer's own module directory, so
multi-module inter-project dependencies resolve the same way
`cfg-lang/dap-java--build-compile-attach' already relies on for regular app
launches.

For a JUnit method run (not TestNG, not a whole-class run), the \"-m\"
selector is resolved at shell-execution time via
`cfg-lang/dap-java--method-selector-shell-snippet' rather than passed as the
literal method name, so parameterized test methods resolve
correctly (see that function's docstring)."
  (-let* ((run-method? (and dwim? (dap-java-test-method-at-point t)))
          (to-run (if run-method?
                      (dap-java-test-method-at-point)
                    (dap-java-test-class)))
          (test-class-name (cl-first (s-split "#" to-run)))
          (method-name (and run-method? (cl-second (s-split "#" to-run))))
          (jdtls-ws (or (lsp-find-workspace 'jdtls)
                       (user-error "jdtls is not running. Open a Java file first")))
          (class-path (s-join dap-java--classpath-separator
                              (cfg-lang/dap-java--resolve-test-classpath test-class-name)))
          (test-file (buffer-file-name))
          (selector-snippet (and method-name (not dap-java-use-testng) test-file
                                 (cfg-lang/dap-java--method-selector-shell-snippet
                                  test-file test-class-name method-name)))
          (method-selector-arg (if selector-snippet
                                   (format dap-java--var-format "TEST_SELECTOR")
                                 to-run))
          (prog-list (if dap-java-use-testng
                         (cl-list* runner
                                   "-cp" (format dap-java--var-format "JUNIT_CLASS_PATH")
                                   "org.testng.TestNG"
                                   "-d" dap-java-testng-report-dir
                                   (if (and (s-contains? "#" to-run) run-method?) "-methods" "-testclass")
                                   (if run-method? (s-replace "#" "." to-run) test-class-name)
                                   dap-java-test-additional-args)
                       (cl-list* runner "-jar" dap-java-test-runner
                                 "-cp" (format dap-java--var-format "JUNIT_CLASS_PATH")
                                 (if (and (s-contains? "#" to-run) run-method?) "-m" "-c")
                                 (if run-method? method-selector-arg test-class-name)
                                 dap-java-test-additional-args)))
          (test-run-cmd (s-join " " prog-list))
          (run-block (concat (or selector-snippet "") test-run-cmd))
          (build-root (lsp--workspace-root jdtls-ws))
          (needs-compile? (or (null test-file)
                              (cfg-lang/dap-java--test-needs-compile-p test-file)))
          (build-cmd (and needs-compile?
                          (cfg-lang/dap-java--default-test-compilation-command build-root)))
          (full-cmd (if build-cmd
                        (format "(cd %s && %s) && { %s ; }"
                                (shell-quote-argument build-root)
                                build-cmd
                                run-block)
                      run-block)))
    (unless needs-compile?
      (message "DAP Java: %s is up to date; skipping test-compile" test-class-name))
    (list :program-to-start full-cmd
          :environment-variables `(("JUNIT_CLASS_PATH" . ,class-path))
          :name to-run
          :cwd (lsp-java--get-root))))

(defun cfg-lang/dap-java--start-debug-adapter-port ()
  "Return a fresh JDT debug adapter port for the running jdtls session.
Same pattern as the `debug-adapter-port' binding in
`cfg-lang/dap-java--build-compile-attach': uses `lsp-request-async' +
`accept-process-output' instead of `lsp-send-execute-command'.

Debug test method/class used to get `:debugServer' for free from
upstream's `dap-java--populate-default-args' (via `dap-debug'), which
calls `(lsp-send-execute-command \"vscode.java.startDebugSession\")'
synchronously. That command is the FIRST thing to trigger jdtls's debug
plugin to actually initialize its debug-session machinery in a given
jdtls process, so only the very first invocation in a session is
slow/racy; every later call hits an already-warm plugin and returns
quickly, which is why the failure this function fixes --
`dap--open-network-stream: Wrong type argument: stringp, \(:jsonrpc
...)', i.e. :debugServer ending up bound to the raw outgoing request
object instead of the port, followed by the JVM sitting stuck at
\"Listening for transport dt_socket\" forever -- only ever showed up on
the first debug-test run per Emacs session. Polling via
`accept-process-output' with a generous 30s deadline, instead of
whatever synchronous wait upstream's call relies on, covers that slow
first response directly rather than needing any special-casing for it."
  (let* ((jdtls-ws (or (lsp-find-workspace 'jdtls)
                       (user-error "jdtls is not running. Open a Java file first")))
         (result nil)
         (done nil))
    (with-lsp-workspace jdtls-ws
      (lsp-request-async
       "workspace/executeCommand"
       (list :command "vscode.java.startDebugSession")
       (lambda (res) (setq result res done t))
       :error-handler
       (lambda (err)
         (message "DAP Java: startDebugSession error: %S" err)
         (setq done t))
       :mode 'detached))
    (let ((deadline (+ (float-time) 30)))
      (while (and (not done) (< (float-time) deadline))
        (accept-process-output nil 0.1)))
    (or result
        (user-error
         (concat "vscode.java.startDebugSession did not return a port. "
                 "Ensure the Java debug plugin bundle is loaded "
                 "(check `lsp-java-bundles') and that jdtls has "
                 "finished indexing")))))

*** DAP Java: project =.vscode/launch.json= configuration
~dap-mode~ is the Emacs client for the [[https://microsoft.github.io/debug-adapter-protocol/][Debug Adapter Protocol (DAP)]]. DAP is the
same wire protocol used by VS Code to communicate with language-specific debug
adapters (such as the Microsoft Java Debug Extension). Emacs with ~dap-mode~
acts as a DAP client in the same way VS Code does, so the two share the same
configuration file format: =.vscode/launch.json=.

The connection is:

#+begin_example
  =.vscode/launch.json=          (project config, shared with VS Code)
         │
         │  =M-x dap-debug= reads the JSON, expands =${workspaceFolder}=,
         │  and presents the "name" fields as a selection menu.
         ▼
  =cfg-lang/dap-java--debug-provider=  (provider registration)
         │
         │  Inspects "console" field; if "integratedTerminal" ->
         │  converts to compile_attach (=server=y=) flow.
         ▼
  Eclipse JDT Debug Adapter    (=~/.emacs.d/eclipse.jdt.ls/...=)
         │
         │  DAP protocol over TCP (port from =vscode.java.startDebugSession=)
         ▼
  JVM JDWP agent               (=-agentlib:jdwp=…,server=y,address=localhost:PORT=)
#+end_example

Because ~dap-mode~ understands the standard VS Code launch schema, the same
=.vscode/launch.json= you use with VS Code works in Emacs without modification.
Fields prefixed with =dap-= (e.g. =dap-compilation=) are Emacs extensions
understood only by ~dap-mode~ and ignored by VS Code.

Therefore, each Java project that you want to debug must have a
=.vscode/launch.json= file at the workspace root. ~dap-mode~ reads this file
when you invoke =dap-debug= (=M-x dap-debug=) and selects a configuration by
name. The =cfg-lang/dap-java--debug-provider= installed under provider
registration then routes any =launch= configuration that targets
=integratedTerminal= through the =compile_attach= flow described above.


**** Minimum required fields

| Field                 | Purpose                                                          |
|-----------------------+------------------------------------------------------------------|
| =type=                | Must be ="java"= - selects the Java debug provider.              |
| =request=             | Must be ="launch"= - the provider converts it to compile_attach. |
| =name=                | Human-readable label shown in the dap-debug selection menu.      |
| =mainClass=           | Fully-qualified main class (e.g. =com.example.app.Application=). |
| =projectName=         | Maven/Gradle project name, used to resolve the classpath.        |
| =cwd=                 | Working directory; use =${workspaceFolder}= for the repo root.   |
| =console=             | Must be ="integratedTerminal"= to trigger the compile_attach     |
|                       | flow. Use ="internalConsole"= to fall back to the default        |
|                       | JDT launch flow (no vmArgs forwarding).                          |
| =vmArgs=              | JVM arguments for the *debugged process* (not the language       |
|                       | server). Spring Boot =−D= properties belong here.                |
| =args=                | Program arguments passed after the main class name.              |
| =env=                 | Extra environment variables (e.g. =SPRING_PROFILES_ACTIVE=).     |


**** Optional =dap-*= fields

| Field                 | Purpose                                                          |
|-----------------------+------------------------------------------------------------------|
| =dap-compilation=     | **Optional.** Shell command run by dap-mode *before* launching.  |
|                       | If omitted, auto-detected as described above.                    |
| =dap-compilation-dir= | **Optional.** Directory for =dap-compilation=.                   |
|                       | If omitted, defaults to =${workspaceFolder}=.                    |

Fields prefixed with =dap-= (e.g. =dap-compilation=, =dap-compilation-dir=) are
**optional** Emacs extensions. If omitted, our ~dap-mode~ helpers provide
sensible fallbacks:

- If =dap-compilation= is missing, we will attempt to auto-detect the build tool
  at the workspace root:
  - If a =pom.xml= is found, it uses =mvn compile=.
  - If a =build.gradle= or =build.gradle.kts= is found, it uses =gradle
    compileJava=.
  - If neither is found, no build step is run (the value is nil).
- If =dap-compilation-dir= is missing, the workspace root is used as the working
  directory for the build command.

These fields are ignored by VS Code and only affect Emacs. You only need to
specify them if you want to override the auto-detected defaults (for example, to
use a custom build script or a submodule directory).


**** Example =.vscode/launch.json= for a Spring Boot application

#+begin_src json
{
  "version": "0.2.0",
  "configurations": [
    {
      "type": "java",
      "request": "launch",
      "name": "App Name - dev - Build and Debug",
      "mainClass": "com.example.app.Application",
      "projectName": "my-spring-application",
      "cwd": "${workspaceFolder}",
      "console": "integratedTerminal",
      "vmArgs": [
        "-Dserver.port=8081",
        "-Dspring.datasource.url=jdbc:postgresql://localhost:5432/orders"
      ],
      "args": [],
      "env": {
        "SPRING_PROFILES_ACTIVE": "local,dev"
      },
      // The following dap-* fields are optional:
      // "dap-compilation": "mvn compile -q", // If omitted, auto-detected or skipped
      // "dap-compilation-dir": "${workspaceFolder}" // If omitted, defaults to workspace root
    }
  ]
}
#+end_src

**** Notes

- =projectName= must match the =<artifactId>= in the root =pom.xml= (Maven) or
  the Gradle project name exactly--JDT uses it to resolve classpaths.
- =vmArgs= here controls *your application*, not the language server. Do not
  confuse it with =lsp-java-vmargs= which is for the JDT LS process itself.
- The =dap-compilation= step (if present or auto-detected) runs synchronously
  before the JVM starts; if it fails, the debug session is aborted. For Maven,
  use =-q= (Maven quiet) to reduce noise.
- Add =.vscode/launch.json= to your project =.gitignore= if the values contain
  environment-specific secrets or local paths.

*** DAP Java: inline test links in =*Test.java= buffers
In test files (matching =*Test.java=), class names and test method names are
decorated as clickable inline links so you can run or debug a specific test
without leaving the buffer. The links are only added in files whose name ends
with =Test.java=, so production code is not affected.

Each link style is distinct so you can see at a glance what an action will do:

- Class name links are underlined in green -> run or debug all tests in class.
- Method name links are underlined in orange -> run or debug that method only.

Test method detection covers all visibility modifiers (=public=, =protected=,
=private=, or package-private) so it handles both JUnit 4 (=public void=) and
JUnit 5 (package-private =void=) conventions.

Keyboard and mouse shortcuts (only active in =*Test.java= buffers):

- =click= - run the test at point (no debugger, fast feedback).
- =C-S-click= - debug the test at point (attaches the debugger, hits
  breakpoints).
- =C-c j= - run the test at point (keyboard equivalent of click).
- =C-c C-j= - debug the test at point (keyboard equivalent of C-S-click).

All shortcuts work whether the cursor is on a link or anywhere else in the file;
when on a link the link action is used, otherwise LSP symbols resolve the
enclosing class or method.

#+begin_src emacs-lisp
(defun cfg-lang/dap-java-run-test-at-point ()

If point is on an inline test link, activate its run action.
Otherwise fall back to `cfg-lang/dap-java-run-test-method'."
  (interactive)
  (if (button-at (point))
      (push-button)
    (cfg-lang/dap-java-run-test-method)))

(defun cfg-lang/dap-java-debug-test-at-point ()

** Java environment bootstrap
~exec-path-from-shell~ uses a login shell (=-l= flag), which on Linux sources
=.zprofile= / =.profile= but NOT =.zshrc= / =.bashrc=. SDKMAN installs its
initialisation into =.zshrc= / =.bashrc=, so Emacs never picks up the
SDKMAN-managed Java from the login shell alone. The fix is to read the
=~/.sdkman/candidates/java/current= symlink directly -- this is always set by
=sdk use= / =sdk default= and requires no hardcoded version.

If SDKMAN is not installed the function is a no-op and Emacs falls back to
whatever Java is already on =exec-path=.

#+begin_src emacs-lisp
(with-eval-after-load 'lsp-java
  (defvar lsp-java-java-path)

  (defun cfg-lang/bootstrap-sdkman-java ()
    "Bootstrap SDKMAN's current Java into Emacs's environment.
Sets JAVA_HOME, exec-path, PATH, and `lsp-java-java-path' from the
`~/.sdkman/candidates/java/current' symlink. No version is hardcoded.
IDempotent: skips PATH/JAVA_HOME patches when SDKMAN is already present.
Falls back silently to system Java when SDKMAN is not installed.
Call interactively after switching Java with `sdk use java X.X.X'
outside Emacs, then invoke `jal-lsp-java-switch-java-version' to
update LSP without restarting Emacs."
    (interactive)
    (let* ((sdkman-java-dir (expand-file-name "~/.sdkman/candidates/java/current"))
           (java-bin-dir    (expand-file-name "bin" sdkman-java-dir))
           (java-bin        (expand-file-name "java" java-bin-dir)))
      (cond
       ((file-executable-p java-bin)
        ;; Only patch JAVA_HOME/PATH if exec-path-from-shell did not already
        ;; pick up SDKMAN (idempotent: skip when JAVA_HOME already points there).
        (unless (string-prefix-p sdkman-java-dir (or (getenv "JAVA_HOME") ""))
          (setenv "JAVA_HOME" sdkman-java-dir)
          (setenv "PATH" (concat java-bin-dir path-separator (getenv "PATH")))
          (add-to-list 'exec-path java-bin-dir))
        ;; Pin lsp-java-java-path only when it has not already been set to a
        ;; non-SDKMAN-current path by the user (e.g. via cfg-lang/java-switch-version).
        ;; This prevents re-loading the config from undoing a live version switch.
        (let ((current-path (bound-and-true-p lsp-java-java-path)))
          (when (or (null current-path)
                    (string= current-path "java")
                    ;; Still pointing at SDKMAN current: safe to update.
                    (string-prefix-p sdkman-java-dir current-path))
            (setq lsp-java-java-path java-bin)
            (message "SDKMAN Java bootstrapped: %s" java-bin))))
       ((file-directory-p (expand-file-name "~/.sdkman/candidates/java"))
        ;; SDKMAN is installed but no `current' version is selected.
        (message "SDKMAN found but no current Java selected; using system Java."))
       ;; SDKMAN not installed -- silent fallback to system Java.
       )))

  (cfg-lang/bootstrap-sdkman-java))
#+end_src

** LSP workspace cache and Java switch workflow
Since =lsp-java-configuration-runtimes= is already populated with all SDKMAN
versions (via =cfg-lang/lsp-java-discover-runtimes=), there is no need to touch the
system SDKMAN default (=sdk use= / =sdk default=) when switching Java within
Emacs. The switch is Emacs-session-local only: it does not affect your shell,
other terminals, or other projects.

Set =cfg-lang/java-clean-workspace-on-switch= to =nil= if you want to skip the
workspace cache deletion when switching Java versions (useful when staying on
the same major version and wanting a faster iteration cycle).

#+begin_src emacs-lisp
(defvar cfg-lang/java-clean-workspace-on-switch t
  "When non-nil, delete the LSP workspace cache on every Java version switch.
Set to nil to skip cache deletion when staying on the same major version.")

(defun cfg-lang/java--candidate-from-runtime (runtime)
  "Return the java binary path from RUNTIME plist, or nil if not executable."
  (when-let ((home (plist-get runtime :path)))
    (let ((bin (expand-file-name "bin/java" home)))
      (when (file-executable-p bin) bin))))

(defun cfg-lang/java--collect-candidates (current-path)
  "Return a deduplicated list of java executables to offer for selection.
Starts from CURRENT-PATH, adds system java if available, then all
runtimes from `lsp-java-configuration-runtimes'."
  (let* ((from-runtimes
          (delq nil
                (mapcar #'cfg-lang/java--candidate-from-runtime
                        (append (bound-and-true-p lsp-java-configuration-runtimes) nil))))
         (system-java (executable-find "java"))
         (all (delete-dups
               (delq nil
                     (append (list current-path)
                             (when (and system-java
                                        (not (string= current-path system-java)))
                               (list system-java))
                             from-runtimes)))))
    all))

(defun cfg-lang/java--sync-env (java-bin)
  "Patch JAVA_HOME, PATH, and variable `exec-path' for JAVA-BIN in this session.
Does not affect the shell or any system processes."
  (let* ((java-home (file-name-directory
                     (directory-file-name (file-name-directory java-bin))))
         (bin-dir   (expand-file-name "bin" java-home)))
    (setenv "JAVA_HOME" java-home)
    (setenv "PATH" (concat bin-dir path-separator (getenv "PATH")))
    (add-to-list 'exec-path bin-dir)))

(defun cfg-lang/java--clean-workspace ()
  "Delete ~/.emacs.d/workspace/ unconditionally (no prompt).
Respects `cfg-lang/java-clean-workspace-on-switch'."
  (when cfg-lang/java-clean-workspace-on-switch
    (let ((workspace-dir (expand-file-name "workspace" user-emacs-directory)))
      (when (file-directory-p workspace-dir)
        (delete-directory workspace-dir t)
        (message "LSP workspace cache cleared.")))))

(defun cfg-lang/java--apply-selection (chosen current-path)
  "Set `lsp-java-java-path' to CHOSEN and, if changed, sync env and restart LSP.
Also syncs JAVA_HOME, PATH, and the variable `exec-path' and deletes the
workspace cache before restarting, so jdtls starts fresh with the correct JDK.
CURRENT-PATH is the existing JDK path."
  (defvar lsp-java-java-path)
  (setq lsp-java-java-path chosen)
  (if (string= chosen current-path)
      (message "Java version unchanged (%s)." chosen)
    (message "Switching to Java at '%s'..." chosen)
    (cfg-lang/java--sync-env chosen)
    (cfg-lang/java--clean-workspace)
    ;; jal--lsp-java-restart is still used so jal's vmargs/agent injection runs.
    (when (fboundp 'jal--lsp-java-restart)
      (jal--lsp-java-restart))))

(defun cfg-lang/java-switch-version ()
  "Interactively switch the Java version for this Emacs session.
Picks from all versions in `lsp-java-configuration-runtimes'. Updates
JAVA_HOME, PATH, the variable `exec-path', and `lsp-java-java-path'
session-locally. Optionally cleans the LSP workspace cache before
restarting jdtls, controlled by `cfg-lang/java-clean-workspace-on-switch'."
  (interactive)
  (require 'lsp-java)
  (defvar lsp-java-java-path)
  (let* ((current (or (bound-and-true-p lsp-java-java-path) "java"))
         (candidates (cfg-lang/java--collect-candidates current)))
    (if (< (length candidates) 2)
        (message "No alternative Java versions found; only available: %s" current)
      (let ((chosen (completing-read
                     (format "Java version (current: %s): " current)
                     candidates nil t)))
        (cfg-lang/java--apply-selection chosen current)))))

(defun cfg-lang/java--detect-build-command (dir)
  "Return the build command for project in DIR, or nil if none is found.
Detects Maven (pom.xml) and Gradle (build.gradle / build.gradle.kts).
Returns nil and messages the user when no recognised build file exists."
  (cond
   ((file-exists-p (expand-file-name "pom.xml" dir))
    "mvn clean install -DskipTests")
   ((file-exists-p (expand-file-name "build.gradle" dir))
    "./gradlew clean build -x test")
   ((file-exists-p (expand-file-name "build.gradle.kts" dir))
    "./gradlew clean build -x test")
   (t
    (message "No pom.xml or build.gradle found in %s; skipping rebuild." dir)
    nil)))

(defun cfg-lang/java-switch-and-rebuild (project-dir)
  "Switch Java, clean workspace, and rebuild PROJECT-DIR.
Calls `cfg-lang/java-switch-version' (session-local, no SDKMAN system change),
auto-detects Maven or Gradle, and runs the appropriate build command with
the newly selected JAVA_HOME. Aborts the build step if no build file is found."
  (interactive
   (list (read-directory-name "Project directory: "
                              (or (and (fboundp 'lsp-workspace-root)
                                       (lsp-workspace-root))
                                  default-directory))))
  (cfg-lang/java-switch-version)
  (let* ((project-dir   (expand-file-name project-dir))
         (build-command (cfg-lang/java--detect-build-command project-dir)))
    (when build-command
      (let* ((java-bin  (bound-and-true-p lsp-java-java-path))
             (java-home (when java-bin
                          (file-name-directory
                           (directory-file-name (file-name-directory java-bin)))))
             (default-directory project-dir)
             (process-environment
              (if java-home
                  (cons (format "JAVA_HOME=%s" java-home) process-environment)
                process-environment)))
        (message "Rebuilding %s with: %s" project-dir build-command)
        (compilation-start build-command 'compilation-mode)))))

** Package Rename Prototype
This section is a small, self-contained prototype for a package rename for
~lsp-java~. The package rename is implemented as a single batch resource move
over all Java files in the package subtree.

#+begin_src emacs-lisp
(defun cfg-lang/lsp-java--buffer-package-name ()
  "Return the Java package declared in the current buffer."
  (save-excursion
    (goto-char (point-min))
    (when (re-search-forward "^package[ \t]+\\([[:alnum:]_.]+\\)[ \t]*;" nil t)
      (match-string-no-properties 1))))

(defun cfg-lang/lsp-java--package-rename-default (package-name)
  "Return a conservative default rename target for PACKAGE-NAME."
  (if (string-match "\\`\\(.+\\)\\.\\([^.]+\\)\\'" package-name)
      (format "%s.%s_renamed" (match-string 1 package-name) (match-string 2 package-name))
    (concat package-name "_renamed")))

(defun cfg-lang/lsp-java--package-root-dir ()
  "Return the directory that acts as the package subtree root."
  (unless buffer-file-name
    (user-error "Package rename requires a file-visiting buffer"))
  (file-name-as-directory (file-name-directory buffer-file-name)))

(defun cfg-lang/lsp-java--project-source-root ()
  "Return the source root containing the current Java package tree.
This strips the current package path from variable `buffer-file-name' so package
destinations can be built relative to the source root instead of the current
leaf package directory."
  (let* ((package-name (or (cfg-lang/lsp-java--buffer-package-name)
                           (user-error "Current buffer does not declare a Java package")))
         (package-root (cfg-lang/lsp-java--package-root-dir))
         (package-path (file-name-as-directory
                        (replace-regexp-in-string "\\." "/" package-name))))
    (if (and (string-suffix-p package-path package-root)
             (> (length package-root) (length package-path)))
        (substring package-root 0 (- (length package-root) (length package-path)))
      (user-error "Cannot derive Java source root from %s" package-root))))

(defun cfg-lang/lsp-java--package-java-files (root-dir)
  "Return every Java source file underneath ROOT-DIR."
  (seq-filter #'file-regular-p
              (directory-files-recursively root-dir "\\.java\\'")))

(defun cfg-lang/lsp-java--package-destination-dir (source-root new-package)
  "Return the destination directory for NEW-PACKAGE.
SOURCE-ROOT is the Java source root that contains the package subtree."
  (expand-file-name (replace-regexp-in-string "\\." "/" new-package)
                    (file-name-as-directory source-root)))

(defun cfg-lang/lsp-java--save-modified-project-buffers (project-root)
  "Save modified file buffers below PROJECT-ROOT after a JDTLS workspace edit."
  (dolist (buffer (buffer-list))
    (with-current-buffer buffer
      (when-let* ((file (buffer-file-name))
                  ((string-prefix-p project-root file))
                  ((buffer-modified-p)))
        (save-buffer)))))

(defun cfg-lang/lsp-java--retarget-package-buffers (old-root new-root)
  "Update visited Java buffers after OLD-ROOT has moved to NEW-ROOT."
  (let ((old-root (file-name-as-directory old-root))
        (new-root (file-name-as-directory new-root)))
    (dolist (buffer (buffer-list))
      (with-current-buffer buffer
        (when-let* ((file (buffer-file-name))
                    ((string-prefix-p old-root file)))
          (set-visited-file-name
           (expand-file-name (string-remove-prefix old-root file) new-root) t t))))))

(defun cfg-lang/lsp-java--ensure-workspace ()
  "Return a live JDTLS workspace for the current buffer.
Wait briefly for the workspace that is already starting from the current
buffer's `lsp-deferred' hook."
  (let ((buffer-path (buffer-file-name))
        workspace)
    (unless buffer-path
      (user-error "Package rename requires a file-visiting buffer"))
    (cl-labels ((current-jdtls-workspace ()
                  (or (lsp-find-workspace 'jdtls buffer-path)
                      (lsp-find-workspace 'jdtls)
                      (when (fboundp 'lsp-workspaces)
                        (seq-find (lambda (ws)
                                    (eq (lsp--workspace-server-id ws) 'jdtls))
                                  (lsp-workspaces))))))
      (setq workspace (current-jdtls-workspace))
      (let ((deadline (+ (float-time) 10)))
        (while (and (not (and workspace
                               (eq (lsp--workspace-status workspace) 'initialized)))
                    (< (float-time) deadline))
          (accept-process-output nil 0.1)
          (setq workspace (current-jdtls-workspace))))
      (if (and workspace (eq (lsp--workspace-status workspace) 'initialized))
          workspace
        (user-error "JDTLS is still initializing. Wait for LSP to finish and try again")))))

(defun cfg-lang/lsp-java-move-package (new-package)
  "Move the current Java package subtree to NEW-PACKAGE.
The filesystem move is performed through `rename-file' so lsp-mode asks JDTLS
to update package declarations and references before the directory moves."
  (interactive
   (let* ((package-name (or (cfg-lang/lsp-java--buffer-package-name)
                            (user-error "Current buffer does not declare a Java package")))
          (default (cfg-lang/lsp-java--package-rename-default package-name)))
     (list (read-string (format "Rename package %s to: " package-name) default))))
  (message "JDTLS package rename: collecting files...")
  (let* ((package-root (cfg-lang/lsp-java--package-root-dir))
         (source-root (cfg-lang/lsp-java--project-source-root))
         (source-files (cfg-lang/lsp-java--package-java-files package-root)))
    (unless source-files
      (user-error "No Java files found under %s" package-root))
    (message "JDTLS package rename: waiting for workspace...")
    (let* ((jdtls-ws (cfg-lang/lsp-java--ensure-workspace))
           (destination-dir (cfg-lang/lsp-java--package-destination-dir source-root new-package)))
      (when (string= package-root destination-dir)
        (user-error "Package is already named %s" new-package))
      (when (file-exists-p destination-dir)
        (user-error "Destination package already exists: %s" destination-dir))
      (with-lsp-workspace jdtls-ws
        (message "JDTLS package rename: %s -> %s" package-root destination-dir)
        (condition-case err
            (progn
              (make-directory (file-name-directory (directory-file-name destination-dir)) t)
              (message "JDTLS package rename: moving directory and requesting edits...")
              ;; lsp-mode's `rename-file' advice asks JDTLS for edits before
              ;; moving the directory.  Those edits are applied to buffers.
              (rename-file package-root destination-dir)
              (cfg-lang/lsp-java--retarget-package-buffers package-root destination-dir)
              (message "JDTLS package rename: saving package and reference edits...")
              (cfg-lang/lsp-java--save-modified-project-buffers source-root)
              (message "JDTLS package rename: moved %d Java file%s to %s"
                       (length source-files)
                       (if (= (length source-files) 1) "" "s")
                       new-package))
          (error
           (message "JDTLS package rename failed: %S" err)
           (signal (car err) (cdr err))))))))
#+end_src

**  Google Java Format
The [[https://github.com/google/google-java-format][Google Java Format]] tool reformats Java source code to comply with the [[https://google.github.io/styleguide/javaguide.html][Google
Java Style Guide]] (2-space indentation). We use the pre-built native binary
(GraalVM-based) so no JDK is required at formatting time, and formatting is fast
({{{<}}}100 ms per file).

The native binary is downloaded from the latest GitHub release and placed under
=~/.emacs.d/google-java-format/=. Apheleia uses it as an external formatter for
Java buffers (see the Java setup section below).

#+begin_src sh
GOOGLE_JAVA_FORMAT_VERSION="1.25.0"
GOOGLE_JAVA_FORMAT_DIR="$HOME/.emacs.d/google-java-format"
GOOGLE_JAVA_FORMAT_BIN="$GOOGLE_JAVA_FORMAT_DIR/google-java-format"

is_installed__lang__java__google_java_format() {
  [ -x "$GOOGLE_JAVA_FORMAT_BIN" ]
}

install__lang__java__google_java_format() {
  if ! is_installed__lang__java__google_java_format; then
    local arch os binary_name
    arch="$(uname -m)"
    os="$(uname -s | tr '[:upper:]' '[:lower:]')"
    case "${os}_${arch}" in
      linux_x86_64)  binary_name="google-java-format_linux-x86-64" ;;
      linux_aarch64) binary_name="google-java-format_linux-arm64" ;;
      darwin_arm64)  binary_name="google-java-format_darwin-arm64" ;;
      ,*)
        log_error "No pre-built google-java-format binary for ${os}_${arch}."
        return 1
        ;;
    esac
    mkdir -p "$GOOGLE_JAVA_FORMAT_DIR"

    chmod +x "$GOOGLE_JAVA_FORMAT_BIN"
  fi
}
